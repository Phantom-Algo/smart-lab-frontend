# 智慧实验室数据库文档

# 基本规范

## 表名

- 表名统一使用小写字母 \+ 下划线

- 表名使用业务含义明确的英文单词

- 统一使用单数形式

## 字段名

- 字段名统一使用小写字母 \+ 下划线

- 常用字段名命名规则：

    |    含义|    字段命名|
    |---|---|
    |    主键|    id|
    |    外键 / 关联对象id|    xxx\_id|
    |    编号|    xxx\_no|
    |    编码|    xxx\_code|
    |    类型|    xxx\_type|
    |    状态|    xxx\_status|
    |    数量|    xxx\_quantity|
    |    金额|    xxx\_amount|
    |    时间|    创建时间：created\_at<br>    更新时间：updated\_at<br>    删除时间：deleted\_at<br>    通用：xxx\_at|
    |    布尔值|    is\_xxx|

## 字段类型规范

- 时间字段：`DATETIME`

- 布尔值 / 状态值：`TINYINT UNSIGNED`

- 小数量值：`INT UNSIGNED`

- 主键 / 大数量值：`BIGINT UNSIGNED`

- 结构不稳定的扩展数据：`JSON`

## 索引命名

- 主键：`pk_xxx`（不过一般不需要单独命名）

- 唯一索引：`uk_xxx`

- 普通索引：`idx_xxx`

- check 约束：`ck_xxx`

⚠️ 注意：**一般不建立物理外键约束**，而是在应用层实现逻辑外键约束

## 表约束

- `ENGINE=InnoDB`

- `DEFAULT_CHARSET=utf8mb4`

- `COLLATE=utf8mb4_0900_ai_ci`（可根据表字段的实际情况进行更换）

## 登录鉴权与个人信息子系统（王润林）

- 权限模型：user\_account \-\> resource\_permission \-\> resource

- user\_account 与 user\_profile：1 : 1

    - 逻辑关联字段：`user_profile.user_id` \-\>` user_account.id`

- user\_account 与 login\_session：1 : N

    - 逻辑关联字段：`login_session.user_id` \-\> `user_account.id`

```SQL
CREATE TABLE user_account (
      id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
      account_no VARCHAR(32) NOT NULL COMMENT '账号编号',
      username VARCHAR(64) NOT NULL COMMENT '登录用户名',

      password_salt VARCHAR(64) NOT NULL COMMENT '密码盐值',

      account_status TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '账号状态：1正常 2停用 3锁定',
      failed_login_count INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '连续登录失败次数',
      lock_expires_at DATETIME NULL COMMENT '锁定失效时间',
      last_login_at DATETIME NULL COMMENT '最后登录时间',
      last_login_ip VARCHAR(45) NULL COMMENT '最后登录IP',
      last_password_changed_at DATETIME NULL COMMENT '最后修改密码时间',
      is_password_reset_required TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '是否首次登录强制改密：0否 1是',
      extra_data JSON NULL COMMENT '扩展数据',
      created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
      updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
      deleted_at DATETIME NULL COMMENT '删除时间',
      PRIMARY KEY (id),
      UNIQUE KEY uk_user_account_account_no (account_no),
      UNIQUE KEY uk_user_account_username (username),
      KEY idx_user_account_user_type (user_type),
      KEY idx_user_account_account_status (account_status),
      KEY idx_user_account_last_login_at (last_login_at),
      CONSTRAINT ck_user_account_user_type CHECK (user_type IN (1, 2, 3)),
      CONSTRAINT ck_user_account_account_status CHECK (account_status IN (1, 2, 3)),
      CONSTRAINT ck_user_account_is_password_reset_required CHECK (is_password_reset_required IN (0, 1))

  COLLATE=utf8mb4_0900_ai_ci
  COMMENT='用户账号表';
```

```SQL
CREATE TABLE `msg_event` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '消息事件主键ID',

    `occurred_at` DATETIME(3) NOT NULL COMMENT '原业务事件发生时间',
    `target_type` VARCHAR(32) NOT NULL COMMENT '目标类型：single / multi / all / all_student / all_teacher / all_manager',
    `targets` JSON DEFAULT NULL COMMENT '事件目标用户快照，single/multi 时必填',
    `template_id` BIGINT UNSIGNED DEFAULT NULL COMMENT '正式模板ID',
    `temp_template` JSON DEFAULT NULL COMMENT '临时模板，如 title/content/format',
    `params` JSON DEFAULT NULL COMMENT '模板参数快照',

    `content_format` VARCHAR(16) NOT NULL DEFAULT 'TEXT' COMMENT '内容格式：TEXT / MARKDOWN / HTML',
    `action_url` VARCHAR(512) DEFAULT NULL COMMENT '用户点击消息后的跳转路径',
    `dispatch_status` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '分发状态：0待处理，1处理中，2已完成，3部分失败，4失败',
    `retry_count` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '重试次数',
    `processed_at` DATETIME(3) DEFAULT NULL COMMENT '消息分发完成时间',
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_msg_event_no` (`event_no`),
    KEY `idx_msg_event_source_type_time` (`source_system`, `message_type`, `occurred_at`),
    KEY `idx_msg_event_dispatch_status` (`dispatch_status`, `updated_at`),
    KEY `idx_msg_event_template_id` (`template_id`),
    CONSTRAINT `fk_msg_event_template_id` FOREIGN KEY (`template_id`) REFERENCES `msg_template` (`id`),
    CONSTRAINT `ck_msg_event_priority` CHECK (`priority` IN (1, 2, 3)),
    CONSTRAINT `ck_msg_event_target_type` CHECK (`target_type` IN ('single', 'multi', 'all', 'all_student', 'all_teacher', 'all_manager')),
    CONSTRAINT `ck_msg_event_content_format` CHECK (`content_format` IN ('TEXT', 'MARKDOWN', 'HTML')),
    CONSTRAINT `ck_msg_event_dispatch_status` CHECK (`dispatch_status` IN (0, 1, 2, 3, 4))
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_0900_ai_ci
  COMMENT='消息主体与内部事件落库记录表';
```

### 补充：lab\_detection\_log 传感器消费字段

为支持 RocketMQ 消费幂等、传感器维度查询和环境预警追溯，`lab_detection_log` 在原有字段基础上增加以下字段。项目尚未进入生产环境，不存在旧数据兼容迁移要求，因此 `event_no` 直接使用 `NOT NULL`。

|字段|类型|约束|说明|
|---|---|---|---|
|`event_no`|`VARCHAR(160)`|`NOT NULL`，唯一索引 `uk_lab_detection_event_no`|IoT 事件编号，用于消费幂等|
|`message_id`|`VARCHAR(64)`|可为空|RocketMQ 消息体中的 messageId，用于日志追踪|
|`sensor_id`|`BIGINT UNSIGNED`|可为空，参与 `idx_lab_detection_sensor_time`|传感器 ID 快照|
|`sensor_no`|`VARCHAR(64)`|可为空|传感器编号快照|
|`detected_at`|`DATETIME(3)`|可为空，参与 `idx_lab_detection_sensor_time`|传感器采集时间|
|`alert_detail`|`JSON`|可为空|异常检测详情快照，记录超阈值指标、当前值、安全范围和超限方向|

`detected_data` 保存原始消息与解析快照，包括 `messageId`、`eventNo`、传感器信息、目标实验室、原始检测数据、未知指标列表和异常指标列表；`status` 仍使用 1 表示正常、2 表示异常告警。

### 关联关系

所有外键关联均为逻辑外键，不在数据库层建立物理外键约束（遵循项目规范）。

- `sensor_type` 1 : N `sensor_data_type`：一种传感器类型可定义多个检测数据项

- `sensor_type` 1 : N `sensor`：一种传感器类型下可注册多个传感器实例

- `sensor` 1 : N `sensor_work_log`：一个传感器可产生多条工作日志

- `sensor.target_id` → `device.id`（当 target\_type=1）或 `lab.id`（当 target\_type=2）

### **核心关联链路说明**

```Plain Text
课程 → 教学任务 → 学生提交 → 成绩评定
  │         │
  │         └── course.id ──► teaching_task.course_id
  │         └── teaching_task.id ──► task_submission.task_id
  │         └── task_submission.id ──► grade_assessment.task_submission_id (可选)
  │
  └── course.id ──► grade_item.course_id
  └── grade_item.id ──► grade_assessment.grade_item_id

课程 → 教学资源
  └── course.id ──► teaching_resource.course_id

课程 → 实验室
  └── course.id ──► course_lab.course_id
  └── lab.id ──────► course_lab.lab_id (关联实验场地管理子系统)
```

### **业务约束汇总**

|约束类型|约束内容|
|---|---|
|课程唯一性|`course_code` 全局唯一|
|课程\-实验室|同一课程\+实验室组合唯一绑定|
|提交版本|同一学生\+同一任务可多次提交，`version_no` 自增标记版本|
|成绩唯一|同一评定项\+同一学生唯一一条成绩记录|
|权重约束|同一课程下所有 `grade_item.item_weight` 之和 = 100（应用层校验）|
|评分约束|`score <= full_score`（应用层校验）|
|成绩发布|已发布成绩不可由教师直接修改，需管理员解锁|

### **关键索引策略**

|索引名|用途|
|---|---|
|`uk_course_code`|课程编码全局唯一|
|`idx_course_semester`|按学期查询课程列表|
|`idx_teaching_task_course_id(task_status)`|教师按课程\+状态查询任务|
|`idx_teaching_task_deadline`|截止时间扫描（定时任务推送提醒）|
|`idx_task_submission_task_id(student_id)`|查某学生某任务的提交|
|`idx_task_submission_task_status`|教师查看某任务的所有提交（含状态筛选）|
|`idx_grade_assessment_course_id(grade_status)`|按课程查已发布成绩|
|`uk_grade_assessment`|同一评定项同一学生唯一，防重复评分|
|`uk_course_lab`|防止同一课程\+实验室重复绑定|
