### 数据结构定义

> 根据项目整体架构图，3D全景展示子系统自身不产生复杂业务数据。其核心数据只有「场景映射」一项，其余所需数据（实验室信息、传感器数据）均从外部子系统获取。

#### DS-001：实验室3D场景

将每个实验室映射到对应的 3D 展示入口。

| 字段 | 类型 | 必填 | 用途 |
|------|------|:---:|------|
| id | BIGINT UNSIGNED | ✅ | **主键**：自增唯一标识，供 API 增删改查定位（`PUT /scenes/{id}`、`DELETE /scenes/{id}`） |
| labId | BIGINT UNSIGNED | ✅ | **关联实验室**：逻辑外键，指向实验室场地管理子系统的 `lab.id`。前端通过 `GET /api/v1/labs/{labId}` 获取实验室名称、位置等信息 |
| buildPath | VARCHAR(500) | ✅ | **Unity WebGL 路径**：指向构建产物的文件夹。前端拼接为 iframe src：`src="{buildPath}/index.html"`。例如 `unity-game/3D_Lab/` |
| createdAt | DATETIME | ✅ | **创建时间** |

> **表设计原则**：一个实验室只对应一个 3D 场景入口（`lab_id` 设 UNIQUE 约束）。前端展示时，先从本表查 `buildPath`，再从实验室场地管理子系统查实验室详情，两者组合渲染。不建立物理外键，在应用层校验 `lab_id` 有效性。

#### DS-002：IoT 传感器数据（来自物联网环境子系统，仅消费不存储）

3D 展示子系统通过接口实时获取实验室环境数据，用于在 3D 场景中叠加展示设备状态。

| 字段 | 类型 | 来源 | 用途 |
|------|------|------|------|
| labId | VARCHAR(32) | 物联网环境 | **定位实验室**：标识该数据属于哪个实验室，前端用于匹配当前正在展示的场景 |
| timestamp | TIMESTAMP | 物联网环境 | **数据时效**：传感器数据的采集时间。前端根据此字段判断数据是否过期（超过 5 分钟视为离线），并在界面上显示"最后更新时间" |
| temperature | FLOAT | 物联网环境 | **温度 (°C)**：用于 3D 场景中设备颜色映射——<30°C 绿色（正常）、30-40°C 黄色（预警）、>40°C 红色（告警）。同时显示在场景顶部环境面板中 |
| humidity | FLOAT | 物联网环境 | **湿度 (%)**：以悬浮数值标签形式显示在设备上方。湿度偏离正常范围（<30% 或 >70%）时触发提醒 |
| smoke | FLOAT | 物联网环境 | **烟雾浓度**：实验室安全指标。数值异常时 3D 场景中显示烟雾粒子效果 + 弹出安全告警 |
| gas | FLOAT | 物联网环境 | **气体浓度**：检测有害气体泄漏。超标时触发最高级别告警，3D 场景中相关区域闪烁红色 |
| status | ENUM | 物联网环境 | **综合状态**：物联网子系统根据各项指标综合判断的设备健康状态。`normal` 正常显示、`warning` 黄色高亮、`alarm` 红色闪烁+弹窗 |

> **使用方式**：前端通过 `GET /api/v1/iot/labs/{labId}/realtime` 定时轮询（每 5 秒）或通过 WebSocket 订阅实时推送。该数据不存入本子系统数据库——物联网环境子系统负责存储历史数据，本子系统只做实时展示。

#### DS-003：通用响应格式

本子系统所有后端接口统一使用以下 JSON 格式返回数据。

| 字段 | 类型 | 用途 |
|------|------|------|
| code | int | **状态码**：`200` 成功、`400` 参数错误、`401` 未登录、`403` 无权限、`500` 服务器错误。前端拦截器根据 code 决定走成功回调还是错误提示 |
| message | string | **提示信息**：成功时固定为 "success"，失败时包含具体错误原因，如 "labId 不能为空"、"该实验室已存在场景映射"。前端弹窗或 Toast 展示此信息 |
| data | any | **业务数据**：成功时携带具体数据对象或数组。分页场景下固定包含 `list`（数据列表）、`total`（总数）、`page`（当前页）、`pageSize`（每页条数） |

**示例**：

```json
// 成功响应（单条数据）
{ "code": 200, "message": "success", "data": { "id": 1, "labId": 12, "sceneName": "Common_Lab", "buildPath": "unity-game/3D_Lab/", "sceneStatus": 1, "description": "通用实验室3D场景", "extraData": null, "createdAt": "2025-07-10 10:30:00", "updatedAt": "2025-07-14 09:15:00", "deletedAt": null } }

// 分页响应
{ "code": 200, "data": { "list": [...], "total": 48, "page": 1, "pageSize": 20 } }

// 参数错误响应
{ "code": 400, "message": "labId 不能为空", "data": null }
```

### 功能 FR-0003：第一人称控制器实现

| 属性 | 内容 |
|------|------|
| **功能编号** | FR-0003 |
| **功能描述** | 创建 Player GameObject，挂载 CharacterController 和 PlayerMove.cs 脚本，实现 WASD 移动、鼠标视角旋转、重力模拟 |
| **参与角色** | 开发人员 |
| **前置条件** | 1. FR-0002 已完成 2. PlayerMove.cs 脚本已创建在 Assets/Scripts/ 目录下 |
| **基本流程** | 1. 在场景中创建空 GameObject，命名为 "player"，Tag 设为 Player 2. 添加 CharacterController 组件，参数：Height=2, Radius=0.5, SlopeLimit=45, StepOffset=0.3, SkinWidth=0.08 3. 创建子物体 Main Camera，位置设为 (0, 1.6, 0) 4. 挂载 PlayerMove.cs 脚本 5. 在 Inspector 中将 Camera 拖入 cameraTransform 字段 6. 设置参数：moveSpeed=5, gravity=-9.81, mouseSensitivity=2, maxLookAngle=80 7. 运行游戏测试：WASD 移动正常、鼠标旋转正常、空格无反应（重力需等地面碰撞体就绪） |
| **页面描述** | 无（Game 视图测试） |
| **业务规则** | 1. Player 只能挂载 CharacterController，不得同时挂载 CapsuleCollider 2. Camera 必须为 Player 的子物体，本地坐标 X=0, Z=0，Y=1.6（人眼高度） 3. mouseSensitivity 默认 2，可由用户在设置中调整 4. maxLookAngle 默认 80°，防止视角翻转 5. 脚本需包含 AutoFixReferences 自动修复逻辑，避免 Inspector 引用丢失导致崩溃 |
| **异常处理** | 1. 移动无反应 → 检查 CharacterController 是否正确添加，脚本是否 Enabled 2. 视角乱转 → 检查 Camera 是否为 Player 子物体，AutoFixCameraLocalOffset 是否生效 3. 角色穿过地面 → 地面碰撞体未添加或 IsTrigger=true，参见 FR-0004 |
| **输出结果** | 可正常移动和旋转视角的玩家角色 |

### 功能 FR-0004：碰撞系统配置

| 属性 | 内容 |
|------|------|
| **功能编号** | FR-0004 |
| **功能描述** | 为场景中所有建筑结构配置正确的碰撞体，确保玩家无法穿越墙壁、地板等障碍物 |
| **参与角色** | 开发人员 |
| **前置条件** | 1. FR-0002、FR-0003 已完成 2. 所有建筑结构预制体已就位 |
| **基本流程** | 1. 逐一选中每个墙壁 GameObject 2. 检查 Inspector → BoxCollider 组件是否存在 3. 若不存在 → Add Component → BoxCollider 4. 调整 BoxCollider Size 使其包围整面墙（约 4.25×4.25×0.25） 5. **取消勾选 Is Trigger**（关键步骤） 6. 同样检查 floor、roof、pillar、glass_frame 的碰撞体 7. 运行游戏，WASD 走向墙壁验证阻挡效果 |
| **页面描述** | 无（Unity Editor 操作 + Game 视图测试） |
| **业务规则** | 1. 所有建筑结构碰撞体的 IsTrigger 必须为 false 2. 地板碰撞体 IsTrigger=false，确保玩家不会掉落 3. 玩家只能有 CharacterController，不得叠加 CapsuleCollider 4. 预制体中的碰撞体设置可能被场景 PrefabInstance 覆盖，需检查场景 YAML 文件 |
| **异常处理** | 1. 玩家穿透墙壁 → IsTrigger 为 true，改为 false 2. 修改预制体后仍穿透 → 场景 YAML 中 PrefabInstance 的 m_AddedComponents 覆盖了碰撞体设置，需批量修改场景文件中的 IsTrigger 值为 0 3. 玩家被"弹飞" → SkinWidth 过大，调整为 0.08 |
| **输出结果** | 所有墙壁、地板、屋顶正常阻挡玩家移动 |

Web 页面（index.html）添加 window.addEventListener('message', ...) 监听 5. Unity 中测试：按空格键 → 调用 WebBridge.SendDataToWeb(testData) 6. 打开浏览器 Console → 确认收到 testData 消息 |

## 数据库设计

### 关联关系

- `lab_3d_scene.lab_id` → `实验室场地管理子系统.lab.id`：N : 1（多个 3D 场景可关联同一实验室，但业务上限制为 1:1）
- 本子系统仅 1 张表，无内部表间关联
- 不建立物理外键约束，在应用层实现逻辑外键校验

### DDL

```sql
CREATE TABLE lab_3d_scene (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
    lab_id          BIGINT UNSIGNED NOT NULL COMMENT '关联实验室ID，逻辑外键→实验室场地管理子系统.lab.id',
    build_path      VARCHAR(500) NOT NULL COMMENT 'Unity WebGL构建产物相对路径，如 unity-game/3D_Lab/',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_lab_3d_scene_lab_id (lab_id)
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_0900_ai_ci
  COMMENT='实验室3D场景映射表';
```

> **表设计原则**：根据架构图，3D 展示子系统自身数据极简——仅存储「哪个实验室 → 哪个 3D 场景」的映射。实验室详情从实验室场地管理子系统获取，传感器数据从物联网环境子系统获取，不重复存储。
